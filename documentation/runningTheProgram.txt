*CURRENTLY ONLY INTENDED TO RUN ON WINDOWS AND LINUX MACHINES
The program can be initialized and launched in the 3 ways listed below:

1. Launch the program and then enter 0 at the first option and then a non-zero and below particle count value to interactively input all parameters.

2. Launch the program and then enter 0 at the first option and then 0 to start the simulation with the default parameters.

3. Create or edit a file named "simulationConfigs.txt" (The name is case sensitive) in the root directory.
Write desired options. The files format is provided within the "-" borders below.
Replace contents inside parentheses with described contents and remove parentheses.
text after "//" are comments giving additional information, do not include them in the actual file. Do not write in bare decimal point eg (.8, .1, .45).
Write the leading zero before the decimal point eg:(0.8, 0.1, 0.45).
Leave no empty space in each line. Names with spaces in them are not supported.
All seven properties of a particle must be described here
At the end of describing the properties of a particle, end the line with a ';' character.
---------------------------------------------------------------------------------------------------
(NumberOfParticleTypes)
(SimulationBorderArea)
(ParticleTypeName),(ParticlesColorRedValue),(ParticlesColorGreenValue),(ParticlesColorBlueValue),(ParticlesMass),(ParticleRadius),(NumberOfParticles);
(ParticleTypeName2),(ParticlesColorRedValue2),(ParticlesColorGreenValue2),(ParticlesColorBlueValue2),(ParticlesMass2),(ParticleRadius2),(NumberOfParticles2);
//so on...
---------------------------------------------------------------------------------------------------Below is an example within the '-' borders. It describes configuring 3 particle types. With a simulation border area of 81 (thus the sides of the cube are 9 units).
First has the particle type name Carbon and it has rgb color values 0,0,0 (black), has 12 mass, has a radius of 1, and there exists 2 of it.
Then is the particle type is called Hydrogen and it has rgb color values of 0,0,1 (blue), has 1 mass, has a radius of 0.1 and there exists 10 particles of this.
Lastly is the particle type name Oxygen which is colored a light blue with rgb values 0.7,1,0.7, has mass 16, has radius of 0.5, and there exists 2 of it.
---------------------------------------------------------------------------------------------------
3
81
Carbon,0,0,0,12,1,2;
Hydrogen,0,1,0,1,0.1,1;
Oxygen, 0.7,1,0.7,16,0.5,2;
---------------------------------------------------------------------------------------------------

To close the program during the simulation press the escape ("esc") key.

After running the program and closing the application, some "resultant data" are output. 
The first column shows the names of particles types. The column after that each indicate the 
total number of collisions among all particles of that type, within the time period of 
"dataHarvestTimeInterval", which is a variable thats default value is 5. This value can 
be changed by modifying the value assigned to the "dataHarvestTimeInterval" constant 
and recompilling the program.

The longer the program goes for, the more columns would be added. As more "dataHarvests" occur.

Here is an example of a output with explanation.

Carbon : 0,0,8,
Hydrogen, : 0,1,0,
Oxygen : 0,5,7,

The first column shows the names of data types present during the simulation. Carbon, Hydrogen 
and Oxygen. After that, during the first time interval no particle of any data type collided. 
This will usually be the case since the first data harvest occurs as soon as the simulation starts. 

The third row shows the second time interval. Where no particles belonging to the Carbon particle type 
collide. 1 collision occurred with a particle that is of Hydrogen particle type. There were 5 collisions
among particles of the oxygen particle type.

the last row shows that 8 collisions occurred for carbon particles within the third/last time 
interval. No hydrogen particles collided in the last time interval. 7 collisions happened between 
oxygen particles.

The resultant data is also stored in the "resultantData.txt" file in csv format. This file is overwritten 
every run.
